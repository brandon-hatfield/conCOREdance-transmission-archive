Summary:
Bounded cancellable PDF intake is implemented with 159 passing tests; microphone/call capture and Apple audio-to-note drafting are now required beta scope, pending implementation.

Body:
PDF intake now uses one cancellable operation across selection, drop, Print/Open and post-unlock queues. Reading, hashing, per-file encryption and encrypted staging execute away from the UI actor. The defaults are 20 selected files, 25 MiB per file, a 100 MiB read-content budget per batch and a 20-URL waiting tray. Regular-file descriptor validation and bounded chunked reads reject oversized and special files; duplicates and invalid-header reads consume the budget. Intake includes a basic PDF header check, not full PDF parsing.

Privacy protection cancels active intake and prevents late results from modifying a protected or re-unlocked session. Completed originals are retained; cancelled prepared stages are discarded. The review workspace displays limits, progress, cancellation and results. Restore is refused during active intake, and termination cancels intake and waits for cleanup. The final metadata-vault save remains on the existing synchronous path. Cancellation is cooperative; a blocked filesystem syscall may take time to return without blocking the UI actor.

The fresh final full suite passed 159 tests with zero failures, including twelve new PDF intake tests. Coverage includes a 1 GB sparse file, exact limits, folders/symlinks/FIFOs, duplicate and invalid-content byte budgets, waiting-tray overflow, protected queuing, parent-task cancellation, retained completed work and late-result cleanup after lock/re-unlock. Existing original encryption, filing, Print queues, assessment and backup/restore tests passed after migration to await actual intake completion.

Native development build 20261109171422 passed ad hoc signature verification. An isolated synthetic vault accepted Open/file-picker input, skipped duplicate content, displayed review/limit information and rejected a 30 MiB PDF without adding it to review. Controlled asynchronous tests establish in-flight privacy/cancellation behavior; no timed UI performance benchmark is claimed. A separate native unlock attempt using the earlier synthetic fixture in synced Documents stalled in a background open syscall; the temporary local fixture worked. File Provider behavior remains a separate validation item. No real clinical vault or credentials were used.

Complete source is preserved on private branch feature/bounded-pdf-intake-2026-11-09 at commit 57e1709aa29aadff2c5272e4368260e58ac48631, proposed in a draft pull request stacked on the manual-lock branch. The verified bundle records 418a8e9-modified because it was built before the source was committed. PDF_INTAKE_VERIFICATION.md records exact scope and limits. This supersedes the preceding current-state description of unremediated PDF intake; independent review, broad provider/scale tests, reviewed key derivation/recovery, trusted distribution and clinical acceptance remain open.

The owner also expanded the private-beta requirements on November 9: capture both microphone and call audio, transcribe with Apple's on-device tools, and create editable progress-note drafts for clinician review using Apple Intelligence. AUDIO_NOTE_BETA.md records the required workflow and acceptance criteria. That audio-to-note workflow is a new required gate, not a feature implemented by this PDF milestone. The app remains a synthetic-data development preview and is not approved for real clinical records.

Decisions:
- Bound selected files, read content and queued URLs.
- Cancel intake on privacy protection and reject stale results.
- Require microphone plus call-audio transcription and reviewed progress-note drafts before clinical beta.

Next Actions:

- Continue independent security/recovery, provider, signing and clinical acceptance.
