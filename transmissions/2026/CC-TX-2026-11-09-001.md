# Protected Manual Locking and Failed-Save Recovery

Manual locking now protects the native workspace before editor flushing or vault saving. If either operation fails, work is retained behind authentication and can be recovered through a later successful save. Both interactive lock actions use the shared protection path; ordinary successful locking clears the vault session when no editor sheet requires preservation.

The privacy cover hides the entire original window content and toolbar while preserving mounted editor buffers. Later interface updates remain hidden visually and from accessibility. The cover is painted before synchronous I/O, and save-error dialogs wait until authenticated return. Failed-save session retention is UI protection of data still in process memory, not a cryptographically locked memory image.

The final fresh full XCTest suite passed 147 tests with zero failures. Eight focused lock tests also passed. Four new regression tests cover failed writes and recovery, authentication rejection, suspended and failed editor flushes, duplicate lock requests, successful persistence, and native window/toolbar/sheet protection including content added after protection. Packaged native synthetic-vault checks confirmed the rendered failure screen, hidden dashboard accessibility content, wrong-password rejection, authenticated return, deferred error presentation, successful save retry after repairing the isolated destination, and ordinary locking afterward. No real clinical records, credentials or biometric enrollment were used.
