Readable Clinical Workspace, Practice Appearance and Local Touch ID Signing

The observatory overhaul was found on the clinical-preview lineage, not on the older main branch. The current implementation continues the Apple session-audio branch and is published as complete source commit 09b23dddcd733a74760ebcab43b840e535e48fcd on codex/readability-and-practice-branding, in unmerged draft PR 4. The older main baseline and existing development branches are preserved.

The interface now offers persistent text sizes from 100 to 175 percent, defaulting to 125 percent, in Settings and the View menu. Shared surface/text roles replace mixed light backgrounds and night-mode text across clinical editors, cards, actions, sidebar and previews. Paper-based content remains opaque and uses dark text; native controls follow the appropriate appearance. The audit trail starts with five events and expands to all events. Touch ID enrollment has an explicit enabled status box.

Provider photos and optional practice logos can be imported, replaced or removed as local per-Mac appearance preferences. A photo replaces the sidebar initial; a logo replaces the sidebar name. Document Preview retains its ConCOREdance header and places the logo separately as a faint right-hand watermark. Imports normalize orientation, retain proportions/transparency and preserve the previous image after a decode failure. These preferences do not implement provider accounts, practice membership or clinical record access control.

The local missing-entitlement Keychain failure was traced to ad hoc signing. A fresh Apple Development identity and Personal Team provisioning profile were created using Xcode 27.3 beta, and an isolated randomly generated device-only biometric-protected item was successfully added and deleted. The app was installed with the authorized identity and Keychain access group. Owner-reported enrollment and its detection after updates were observed. This is not broad hardware biometric acceptance or a notarized distributable. The development profile expires November 21, 2026 at 02:01 UTC and requires renewal.

The final fresh suite ran 188 tests with two optional real Apple speech/model checks skipped and zero failures. Nine new tests cover text-size rules, foreground/background contrast in four palettes, and appearance persistence/replacement/removal. Installed native checks covered the vault entrance, dashboard, Settings, session drafting surfaces and previews; a selected provider photo was visible in the sidebar. Native password hints and the system chooser were observed, with the owner reporting the field suggestion returning after restart. Domain-matched Password AutoFill is still unconfigured. Arbitrary practice artwork, every sheet/state, biometric failure paths and broader clinical/security/recovery acceptance are not exhaustively verified. Historical November 10 real Apple integration evidence remains historical and was not rerun by this milestone.

The owner requested future practice-level supervisory/admin credentials, managed provider profiles under one practice banner, and secure provider login switching on shared terminals and workstations. This is a roadmap requirement, not implemented functionality. Role/access boundaries, separate identities and encryption/storage boundaries, protected handoff of unsaved work, cache/UI isolation, recovery and revocation must be designed before implementation. Practice administration must be distinguished from clinical-supervision permissions rather than assuming administrative access grants access to clinical records.

This entry updates the earlier local signing and native-screen blockers with scoped November 13 evidence. It does not supersede independent security, clinical workflow, physical audio capture or release-trust gates. No clinical records, personal imagery, passwords, signing profiles or private keys accompany this public record.

Decisions

  • Preserve the observatory direction and current font families while improving readability.
  • Use shared semantic color roles and persistent text-size preferences.
  • Keep photos/logos as optional local appearance preferences; preserve the document header beside the logo watermark.
  • Publish source on a review branch and preserve existing branch history.
  • Treat shared-practice administration and secure provider switching as planned architecture work.

Next Actions

  • Review draft PR 4 and continue native visual and biometric failure/recovery acceptance.
  • Renew the local development profile before expiration and establish a supported release-signing process.
  • Define practice/provider roles, storage permissions and protected switching before multi-provider implementation.
